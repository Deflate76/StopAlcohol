# 배포 버전과 업데이트 이력

`app-build.json`은 기존 GitHub Pages/Jekyll 빌드에서 배포 소스 SHA를 자동으로 담습니다.
`Archive deployment history` 워크플로는 `Rollback-version2`의 Pages 배포 성공 후 이력을
`deployment-history` 브랜치에 보관합니다. 실패·취소 배포는 제외하며, 이력 브랜치에는 공개된
배포 설명과 변경 파일만 저장합니다. 서비스 데이터나 회원 정보는 저장하지 않습니다.

버전은 GitHub Pages 실행 번호에 따라 `v305`처럼 표시됩니다. 같은 실행을 다시 배포하면
`v305.2`처럼 시도 번호를 붙입니다. 기존의 수동 `v14` 표시는 더 이상 수정하지 않습니다.
과거 배포의 번호도 같은 규칙으로 통일하며, GitHub에서 조회할 수 있는 성공 이력을 복원합니다.
기존에 보관한 이력은 GitHub 실행 로그가 만료되어도 삭제하지 않습니다.

사용자에게 설명할 변경 사항은 배포 커밋에 `release-notes/날짜-주제.json`을 새 파일로 추가하세요.
형식은 `{ "title": "배포 제목", "changes": ["변경 내용", "변경 내용"] }`입니다.
설명 파일이 없어도 커밋의 전체 설명과 변경 파일, 증감 줄 수는 자동으로 보관됩니다.
변경 파일 분류만으로 추측한 구체적인 동작 설명은 만들지 않습니다.

이력 갱신만 재실행하려면 Actions에서 `Archive deployment history`를 수동 실행하면 됩니다.
운영 소스 브랜치에 자동 커밋을 만들지 않으며, 이력 저장 때문에 사이트가 재배포되지 않습니다.
